# Тест локального распознавания речи (STT) — GigaAM v3 vs routerai.ru

**Дата:** 2026-10-31 · **ПК:** Intel i7-9850H (6 ядер / 12 потоков), 32 ГБ RAM, без дискретной GPU (инференс на CPU) · **ОС:** Windows 10

**Цель:** понять, стоит ли добавлять в Turbo Whisper локальное распознавание (офлайн-режим) как альтернативу API routerai.ru (openai/whisper-large-v3-turbo).

## Методика

- Аудио: реальные диктовки из истории приложения, 16 кГц моно WAV.
  - Фаза 1: `2026-10-31_210248.wav` (20.7с) — модель GigaAM v3 e2e_rnnt / e2e_ctc (PyTorch 2.8.0+cpu)
  - Фаза 2 (сводная): `2026-10-31_224611.wav` (19.7с) — все варианты на одном файле
- Замер: 1 прогревочный прогон + 3 хронометрируемых, берутся min/avg.
- API-сторона — штатный `WhisperClient` приложения (полный сетевой round-trip).
- RTF = время обработки / длительность аудио (меньше 1.0 = быстрее реального времени).

## Результаты (19.7с аудио, тёплые прогоны)

| Движок | min | avg | RTF | Качество текста |
|---|---|---|---|---|
| 🥇 **GigaAM v3 e2e_ctc → ONNX (onnxruntime)** | **1.13с** | **1.16с** | **0.06×** | идеально, с пунктуацией |
| 🥈 **GigaAM v3 RNNT int8 → sherpa-onnx** | 1.55с | 1.68с | 0.09× | идеально, с пунктуацией |
| 🥉 routerai.ru API (whisper-large-v3-turbo) | 1.72с | ~2.0с | 0.10× | галлюцинация «Продолжение следует...» в обоих прогонах |
| GigaAM v3 e2e_ctc (PyTorch) | 1.71с | 2.12с | 0.11× | идеально |
| GigaAM v3 e2e_rnnt (PyTorch) | 2.32с | 2.62с | 0.13× | идеально |

### Качество (тестовая фраза)

Русский текст все движки распознали одинаково хорошо. Отличия:
- **GigaAM** — чистый текст с аккуратной пунктуацией, без артефактов. Английские вклейки распознаёт хуже Whisper («Charter by Charter Typing» → «Chartar Taping»).
- **Whisper (API)** — английские слова лучше, но стабильно добавляет типичный артефакт «Продолжение следует...» (в приложении его срезает `_clean_hallucination`).

## Важные технические цифры

| Показатель | e2e_ctc (torch) | e2e_ctc (ONNX) | sherpa-onnx (RNNT int8) |
|---|---|---|---|
| Загрузка модели | 10–12с | 5.3с (сессия) | 1.6с |
| Размер модели | 449 МБ | 844 МБ fp32 (→ ~210 МБ после int8-квантизации) | 232 МБ (готовый int8) |
| Зависимости рантайма | torch (~300 МБ) | onnxruntime (~40 МБ) | sherpa-onnx (~18 МБ) |
| Холодный старт 1-го инференса | медленный (15–27с у rnnt) | умеренный | быстрый |

## NVIDIA Parakeet TDT 0.6B v3 (добавлено 2026-11-01)

Мультиязычная модель NVIDIA (25 языков, включая русский, автоопределение языка), 0.6B параметров. Протестирована через тот же движок sherpa-onnx (готовый int8-экспорт `csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8`) — честное сравнение с GigaAM «в лоб».

### Итоговое сравнение всех вариантов (19.7с аудио, CPU i7-9850H)

| Движок | min | avg | RTF | Текст (русская диктовка) |
|---|---|---|---|---|
| 🥇 GigaAM v3 e2e_ctc → ONNX | 1.13с | **1.16с** | 0.06× | идеально |
| 🥈 GigaAM v3 RNNT int8 → sherpa-onnx | 1.55с | 1.68с | 0.09× | идеально |
| 🥉 routerai.ru API | 1.72с | ~2.0с | 0.10× | галлюцинация «Продолжение следует...» |
| NVIDIA Parakeet TDT 0.6B v3 int8 → sherpa-onnx | 2.84с | 2.89с | 0.15× | идеально (идентично GigaAM) |
| GigaAM v3 e2e_ctc (PyTorch) | 1.71с | 2.12с | 0.11× | идеально |
| GigaAM v3 e2e_rnnt (PyTorch) | 2.32с | 2.62с | 0.13× | идеально |

Parakeet: загрузка модели 3.6с, вес int8 ~600 МБ. Качество русского текста идентично GigaAM (оба идеальны).

### Вердикт по Parakeet

Для **русской** диктовки Parakeet проигрывает: **в 2.5 раза медленнее** GigaAM ONNX и в 1.4 раза медленнее API. Его сильная сторона — **мультиязычность**: 25 языков с автоопределением (GigaAM — только русский). Имеет смысл только если понадобится офлайн-распознавание не-русской речи; для этого лучше сравнивать его с Whisper-моделями локально (faster-whisper), а не с GigaAM.

**Итог: для Turbo Whisper оптимальна связка «GigaAM v3 e2e_ctc (ONNX) для русского + API/другой движок для остального»**, Parakeet — как кандидат на мультиязычный офлайн-режим при желании.

## Вывод

**Локальное распознавание реализовывать стоит.** Лучший вариант — **GigaAM v3 e2e_ctc через ONNX Runtime**: в ~1.7 раза быстрее API, качество не уступает (по чистоте выигрывает — нет галлюцинаций), офлайн, бесплатно, приватно.

### Рекомендации по внедрению

1. «Offline mode» в настройках: ONNX-модель скачивается по требованию, держится в памяти (32 ГБ RAM достаточно).
2. Прогрев в фоне при старте приложения (загрузка ONNX-сессии ~5с).
3. Квантизация ONNX fp32 → int8 штатным `onnxruntime.quantization` (844 → ~210 МБ, инференс быстрее).
4. Стриминг-режим выигрывает сильнее всего: нулевая задержка сети на каждый чанк.
5. Фолбэк на API как опция.

**Запасной вариант:** sherpa-onnx + готовый int8-экспорт GigaAM v3 RNNT (1.68с) — минимум интеграционного кода (всё включено: препроцессинг + декодирование + пунктуация), самый лёгкий рантайм.

## Как воспроизвести замеры

Тестовое окружение: `%TEMP%\opencode\gigaam-test\` (venv: torch-cpu, transformers, onnxruntime, sherpa-onnx, gigaam из репозитория).

- `bench_gigaam.py <e2e_ctc|e2e_rnnt>` — API + PyTorch-варианты GigaAM v3 (`ai-sage/GigaAM-v3` через transformers, `trust_remote_code`)
- `bench_onnx_sherpa.py` — ONNX-экспорт e2e_ctc + инференс onnxruntime; sherpa-onnx (экспорт `csukuangfj/sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16`)
- Аудио: `gigaam-test\test.wav`

### Подводные камни окружения

- `transformers` при загрузке `trust_remote_code` требует стаб-пакет `pyannote` (импорты ленивые, только для longform) — достаточно пустых модулей `pyannote`, `pyannote.audio`, `pyannote.audio.pipelines`.
- Экспорт ONNX требует пакет `onnx` (не ставится вместе с onnxruntime).
- Конфиг модели, сохранённый для `gigaam.onnx_utils`, ссылается на `_target_: modeling_gigaam.*` — модуль должен быть импортирован (через загрузку AutoModel или добавление каталога `transformers_modules` в `sys.path`).
- `preprocessor(wavs, wav_lens)` ожидает `wav_lens` = **число сэмплов** (long), не относительную длину.
- Ограничение `.transcribe` в GigaAM — аудио до 25с (для длинных — `transcribe_longform` с pyannote, или ONNX-путь без этого ограничения).
